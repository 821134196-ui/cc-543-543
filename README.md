# LeakFlow · 物业渗漏协同处置

上下楼住户发现渗漏后的协同处置系统：物业登记 → 关阀/排查/试水（带时间照片）→
协商员责任意见与费用方案 → 双方签署 → 修复 → 复验，**复漏自动再开新一轮**。

零三方依赖：Python 3.11 标准库（`http.server` + `sqlite3`）+ 原生前端；
现场照片由内置 PNG 编码器程序化生成并保存在本地磁盘；通知与签收使用模拟适配器。

## 一条命令启动

```bash
./run.sh                 # 默认 http://127.0.0.1:8000/ ，启动即重建复漏演示案例
PORT=8123 ./run.sh       # 换端口
KEEP=1 ./run.sh          # 保留现有数据库，不重建种子
```

打开后右上角可切换五种**视角**（物业 / 维修勘查 / 协商员 / 502 报修户 / 602 楼上户）：
住户视角会自动隐藏另一户的室内隐私证据。

## 演示案例 LK-2026-0920-07

502 三间房同时渗漏 → 602 首次拒绝入户 → 水源暂时无法定位 →
一张 8 月旧照片被误用（标记不删除）→ 二次入户打压定位厨房角阀 →
费用两轮争议后签署 → 修复 → **复验复漏（不同水源）再开案** →
闭水定位 602 卫生间防水层 → 二轮方案签署 → 复验通过结案。

页面包含：楼层叠放示意、证据时间线、入户预约、试水记录、协商方案、修复复验、事件链。

## 领域规则（均由代码与测试强制）

| 规则 | 实现位置 |
| --- | --- |
| 报修方不能修改对方陈述 | `statements` 仅可由本人 `corrects_id` 追加更正，原文保留 |
| 勘查人不能独自批准赔偿 | 方案中 `compensation` 项仅协商员可建；修复须双方签署方案 |
| 每份责任意见引用当时证据版本 | `opinions.snapshot_seq` + 显式 `citations`，意见后不可变 |
| 新证据只触发重新协商 | 旧意见保留；详情页提示「快照后新证据」，新意见产生新快照 |
| 水源未定/多房间/拒入户/旧照误用/复漏/费用分歧 | 均以 `conclusion_tags` 多结论并存，互不覆盖 |
| 方案签署冲突 | 一户拒绝即 `disputed`；同版本不可重复签署；旧版 `superseded` 禁签 |
| 复验复漏 | 案件 `reopened`、`round_no+1`，历轮意见/方案/签署全部留存 |
| 跨户隐私 | 证据 `visibility=unit:<id>`；住户只见公共证据与本户证据 |
| 事件可追溯 | `events` 为 SHA-256 哈希链，详情页实时校验，篡改即变红 |

## 测试

```bash
python3 -m unittest discover -s tests -v
```

覆盖四类要求场景：证据版本（快照冻结/新证据重协商/旧照误用）、跨户隐私、
方案签署冲突（拒签/重复签/旧版禁签/越权批赔偿/改对方陈述）、复验后再开案；
另含哈希链篡改检测、模拟通知签收幂等与种子案例端到端不变量。

## 目录

```
leakflow/
  db.py        SQLite 表结构（事件链/证据版本/签署/复验…）
  services.py  领域服务与权限规则
  png.py       零依赖 PNG 编码器（现场照片生成）
  seed.py      复漏演示案例（固定时间戳，可重复重建）
  server.py    stdlib HTTP 服务 + JSON API + 视图模型
  web/         index.html / styles.css / app.js（原生 JS，无构建）
tests/         unittest 领域测试
run.sh         一键启动（重建种子 + 起服务）
```

## 设计

白、石墨灰与克制的水蓝（`#3e7cb1`）；漏点照片以原始宽高显示、保持原比例，
点击大图可在归一化坐标上标注漏点（随任何缩放等比定位）；费用方案按
修复/赔偿/勘查等责任项逐行列明金额与依据。
