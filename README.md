# 上下楼渗漏协商台账

面向物业的渗漏排查与协商记录系统：登记各方描述、分阶段关阀/排查/试水、**带时间的证据版本**、
入户预约、按责任项列金额的费用方案、签署签收与修复复验。复验发现复漏时旧案封存、再开新案并继承证据链。

- **零依赖**：仅用 Node.js ≥ 22.5 内置能力（`node:sqlite`、`node:http`、`zlib`），`npm install` 都不需要。
- SQLite 保存仅追加的事件链；照片以原始字节存本地；通知与签收走**模拟适配器**（落库 + 写日志，不发真实请求）。

## 一条命令启动（自带复漏案例）

```bash
npm start          # 或 node --no-warnings src/start.js
# 打开 http://localhost:5273
```

首次启动自动播种；已有数据时跳过播种。重置复漏案例：

```bash
npm run reset      # 清空 data/ 后重建
PORT=8080 npm start
npm test           # 10 个测试
```

播种后有三个案件（右上角可切换身份模拟登录）：

| 案件 | 说明 |
|---|---|
| `LS-2026-0907` | 3栋601↔701 主案例，最终**复验失败封存**：含拒入户、多房间同漏、水源未定位、旧照误用、费用争议拒签、重新协商、复漏结论 |
| `LS-2026-0907-R1` | 复漏**再开案**：继承 v1/v2 证据 → 暗管第二漏点 v3 → 新方案 → 复验通过关闭 |
| `LS-2026-0911` | 2栋502↔602 在办案件，用于演示**跨户隐私隔离**（非成员看不到、也操作不了） |

## 页面

- **楼层示意**：楼上/楼下按真实楼层**上下叠放**，中间虚线动画表示渗流路径与待定位状态。
- **登记与陈述**：位置、受损部位、各方描述；只可追加。
- **入户预约 / 分阶段维修（关阀→排查→试水）/ 试水记录**。
- **漏点照片**：服务端返回原图字节，页面用 `width:100%;height:auto` **保持原比例**（元信息显示原始宽高与比例）；
  点击照片任意位置即可以归一化坐标（0..1）标注，**标注不改原文件**（坐标按显示尺寸换算，任何缩放下点位对应同一处）。
- **证据时间线**：仅追加事件链，责任事件带「证据 vN」版本戳。
- **不同结论并存**：水源暂时无法定位 / 多个房间同时渗漏 / 拒绝入户 / 旧照片被误用 / 修复后复漏 / 费用不认可，各自独立留痕。
- **协商方案**：费用按责任项列明金额与依据；显示各方签署（含文档修订号）、批准与质保。
- **修复复验**：通过则关闭；失败自动再开案，顶部队列显示案件谱系，可在原案与新案间跳转。

配色为白、石墨灰与克制的水蓝（`public/styles.css` 顶部变量可整体调色）。

## 关键规则（后端强制，非仅前端隐藏）

- **证据版本**：证据先入草稿，冻结成版本后不可改删（服务层 + SQLite 触发器双重保护）。
  每份责任意见必须引用一个已冻结版本；后续新证据只能冻结新版本、触发**重新协商**出新方案，旧方案原样保留。
- **陈述不可改**：报修方不能修改对方陈述；无更新/删除接口，数据库有触发器兜底。物业可「代录」，但记录归属为被代录住户且标注来源。
- **跨户隐私**：所有案件读取、照片读取、写操作都校验 `case_members` 成员身份，非成员返回 `403 cross_household_denied`；案件列表只返回本人相关案件。
- **赔偿批准**：只有协商员可批准（勘查人、住户均 `403 role_forbidden`），且各责任方全部签署、无拒签才可批准。
- **方案签署冲突**：定稿即锁定文档修订号（1），费用项不可再改；签署携带修订号，不一致返回
  `409 doc_version_conflict`；同一方不可重复签署；任一方拒签则方案 `rejected` 并留「费用不认可」结论。
- **复验再开案**：复验失败 → 旧案 `closed_reopened` 只读封存（复漏结论保留）→ 新建 `*-R1` 案件，
  成员相同，继承全部冻结版本/已入册证据/照片（共用本地文件、新案独立行），随后在新案继续勘查协商。

## 测试覆盖（`test/ledger.test.js`，10 项）

证据版本冻结后不可变与责任意见引用、照片原比例与标注不改原件、跨户隐私（服务层 + HTTP 层 + 列表不泄露）、
陈述归属与禁改、勘查人不能批赔偿、签署修订号冲突/重复签/拒签重新协商、复验失败再开案与继承后再关闭、
拒绝入户结论与阶段阻塞、种子复漏案例完整性。

## 目录

```
src/
  db.js        SQLite 表结构 + 仅追加触发器
  service.js   全部业务规则与权限（事件链、版本、协商、复验）
  server.js    零依赖 HTTP 路由 / 静态文件 / 照片鉴权
  adapters.js  模拟短信·上门通知与纸质签收（notifications/receipts 表 + 日志）
  png.js       零依赖 PNG 生成（种子现场照片）
  seed.js      复漏主案例 + 跨户案例的完整事件链
  start.js     入口：建库 → 播种 → 起服务
public/        前端（原生 HTML/CSS/JS，无构建）
data/          运行产物：leak.db、photos/、adapters/mock-adapter.log
```

模拟身份通过请求头 `X-Party-Id` 传递（前端右上角切换）；生产环境应替换为真实登录中间件，
并把 `src/adapters.js` 换成真实短信/签收通道，业务层接口不变。
